# Tasks — omniroute-llm-pool

Requirement references: **GW** = `specs/llm-pool-gateway/spec.md`, **RG** = `specs/llm-pool-registry/spec.md`, **RT** = `specs/llm-pool-routing/spec.md`, **CT** = `specs/llm-pool-control/spec.md`, **LG** = `specs/llm-pool-ledger/spec.md`, **CS** = `specs/llm-pool-console/spec.md`, **SO** = `specs/supervision-offload/spec.md`. Design decisions: **D1**–**D18** in `design.md`. Gap ids (G-nn) are those of `GAPS.md`.

Tasks marked **[developer]** are his alone and block only what names them.

**Order.** Stage 0 comes first and decides what is built: tasks 1.7, 6.1, 6.2 and 6.3 need no gateway and no pool code. Task 6.3 records one of the four rows of the table in D15; its first record (2026-11-27) is row 1, so 6.4 and 6.5 come next and nothing else is built meanwhile. Tasks 5.2 to 5.6 (the watcher's triage) and group 7 exist only after a "go", which stage 0 alone cannot give: on the row "a model must be tested" the decision stays open until the shadow test of task 6.6 has run, and that test builds 5.2, 5.4 and 5.5 ahead of the "go" once the developer has installed the gateway (1.2). Groups 2 to 4 and the digest task (5.7) wait while the decision is open, except what the shadow test of 6.6 needs from groups 2 and 3 (the pool's `ask` for `wake-triage`); after a "no-go" they are built only if the developer wants the pool for digests alone, and 6.3 records that too.
